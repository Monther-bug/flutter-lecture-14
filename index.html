Piece 1 · The data

ChangeNotifier: our CounterProvider

lib/counter_provider.dart
import 'package:flutter/foundation.dart';

class CounterProvider extends ChangeNotifier {
  int _count = 0; // private: only this class can change it

  int get count => _count; // public, read-only

  void increment() {
    _count++;
    notifyListeners(); // tell every listening widget to rebuild
  }

  // reset() works the same way: _count = 0; notifyListeners();
}
1extends ChangeNotifierour class can notify listeners
2_count starts with _private to this file
3get counta getter, a read-only window to _count
4notifyListeners()The rule: change the data, then call it
No widgets here: it imports foundation.dart, not material.dart. Plain Dart logic.

Piece 3 · The long form

Provider.of<T>(context) and listen: false

CounterPage
// In build(): find it AND listen (rebuild on change)
final counter = Provider.of<CounterProvider>(context);

// In onPressed: find it, but do NOT listen
onPressed: () {
  Provider.of<CounterProvider>(context, listen: false).increment();
},
1Listen (the default)listen is true by default: the widget rebuilds on every notifyListeners()
2listen: falseIn a button we only want to call a method, so we don't listen
Forgetting listen: false in onPressed gives an error (slide 18)

Watch or read?

The short way: context.watch and context.read

Short form (we use this) Same as Use it
context.watch<CounterProvider>()Provider.of<CounterProvider>(context)in build(), to show data (rebuilds)
context.read<CounterProvider>()Provider.of<CounterProvider>(context, listen: false)in onPressed / onChanged, to call methods
Consumer<CounterProvider>(builder: ...)(a widget)to rebuild only a small part of a page
Easy rule: watch to show, read to change
watch and read come from the same import: package:provider/provider.dart

Share data · The provider

Sharing data between screens: ProfileProvider

lib/profile_provider.dart
class ProfileProvider extends ChangeNotifier {
  String _name = 'Ali';

  String get name => _name;

  void changeName(String newName) {
    final trimmed = newName.trim();
    _name = trimmed.isEmpty ? 'Guest' : trimmed;
    notifyListeners();
  }
}
  • GoalHome shows "Hello, Ali"; the Profile page changes the name
  • Go backHome already shows the new name; no callbacks, no pop result
  • The rule"empty name → Guest" lives in the provider, not in a widget

Optional · Dark mode

Optional: ThemeProvider for dark mode

lib/theme_provider.dart
class ThemeProvider extends ChangeNotifier {
  ThemeMode _themeMode = ThemeMode.system; // follow the phone at first

  ThemeMode get themeMode => _themeMode;

  void changeTheme(bool isDark) {
    _themeMode = isDark ? ThemeMode.dark : ThemeMode.light;
    notifyListeners();
  }
}
changeTheme()the same method as _MyAppState in Lecture 10, now in a provider
MyApptheme: buildTheme(Brightness.light), darkTheme: buildTheme(Brightness.dark), themeMode: themeMode (from context.watch<ThemeProvider>())
ThemeButtonLecture 10's button, no callback: isDark comes from Theme.of(context).brightness, and onPressed calls context.read<ThemeProvider>().changeTheme(!isDark)
Home AppBaractions: const [ThemeButton()]

Wrap-up

Summary

Today you learned

  • ChangeNotifier: private data + getters + methods that call notifyListeners()
  • ChangeNotifierProvider / MultiProvider above MaterialApp
  • Watch to show (context.watch, Consumer), read to change (context.read)
  • Provider.of(context) = watch; Provider.of(context, listen: false) = read
  • A change on one screen refreshes every screen that watches
